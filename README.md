# Mohammad Faiyaz Ansari — HSE Officer Portfolio

A premium, single-page personal brand website for an HSE (Health, Safety & Environment) Officer, built with plain **HTML5 + CSS3 + Vanilla JS** — no build step, no framework, deployable straight to **GitHub Pages**.

## 1. What's inside

```
/
├── index.html          → all page content & structure
├── style.css            → design system, layout, animations
├── script.js             → interactivity (no dependencies)
├── robots.txt            → search engine crawl rules
├── sitemap.xml            → single-URL sitemap
├── README.md
└── assets/
    ├── images/           → (add real project/site photos here)
    ├── icons/
    │   └── favicon.svg
    └── resume.pdf         → placeholder — replace with your real resume
```

**Signature element:** every card on the site (skills, certifications, resume preview, contact) is styled as a *permit-to-work tag* — a dashed border with a small punched "grommet hole," echoing the physical safety tags used on real construction sites. The hero features a rotating inspection-stamp graphic and a faint construction blueprint/grid backdrop.

## 3. Deploying to GitHub Pages

1. Create a new GitHub repository (e.g. `faiyaz-hse-portfolio`).
2. Upload every file in this folder to the repository root (keep the `assets/` folder structure intact).
3. In the repo, go to **Settings → Pages**.
4. Under **Source**, choose **Deploy from a branch**, branch `main`, folder `/root`.
5. Save. Your site will be live at `https://<your-username>.github.io/<repo-name>/`.
6. If you use a custom domain, add a `CNAME` file and update `sitemap.xml`, `robots.txt`, and the canonical/Open Graph URLs in `index.html` to match it.

No build tools, `npm install`, or server are required — it's fully static.

## 4. Things to personalize before publishing

- **Resume**: replace `assets/resume.pdf` with your real resume (same filename, or update the `href` in `index.html`).
- **Photo**: `#about` currently uses an illustrated placeholder portrait. Add a real photo to `assets/images/` and swap the `<svg>` block in the `.portrait-frame` for an `<img>` tag.
- **Gallery images**: the Safety Gallery currently renders emoji placeholders generated by `script.js` (`galleryData` array) so the site works instantly with zero external images. Add real, copyright-free site photos to `assets/images/gallery/` and update the `galleryData` array (or the markup directly) to use `<img>` tags instead.
- **Contact details**: update the email, phone, LinkedIn and GitHub links in the Contact section and footer.
- **og-cover.jpg**: add a `1200×630` share image at `assets/images/og-cover.jpg` for nicer link previews on LinkedIn/WhatsApp.
- **Canonical URL**: update every `https://faiyazansari.github.io/` reference in `index.html`, `robots.txt` and `sitemap.xml` to your actual published URL.

## 5. Contact form (EmailJS-ready)

The form in `#contact` works out of the box in **demo mode** (shows a success message, doesn't actually send). To make it send real emails with [EmailJS](https://www.emailjs.com/) (free tier, no backend required):

1. Create a free EmailJS account, an Email Service, and an Email Template.
2. Add the SDK to `index.html`, just before `script.js`:
   ```html
   <script src="https://cdn.jsdelivr.net/npm/@emailjs/browser@3/dist/email.min.js"></script>
   ```
3. In `script.js`, inside the `contactForm.addEventListener("submit", ...)` handler, replace the `setTimeout(...)` demo block with:
   ```js
   emailjs.init("YOUR_PUBLIC_KEY");
   emailjs.sendForm("YOUR_SERVICE_ID", "YOUR_TEMPLATE_ID", contactForm)
     .then(() => {
       submitBtn.disabled = false;
       submitBtn.textContent = "Send Message";
       formStatus.style.color = "#16a34a";
       formStatus.textContent = "Thanks — your message has been sent.";
       contactForm.reset();
     })
     .catch(() => {
       submitBtn.disabled = false;
       submitBtn.textContent = "Send Message";
       formStatus.style.color = "#dc2626";
       formStatus.textContent = "Something went wrong — please email me directly.";
     });
   ```

## 7. Performance & accessibility notes

- No external JS frameworks or heavy libraries — only two Google Fonts requests and no images by default, so the site loads instantly.
- Once you add real photos, use modern formats (WebP/AVIF), reasonable dimensions, and `loading="lazy"` on any `<img>` below the fold to keep Lighthouse Performance near 100.
- Run Lighthouse in Chrome DevTools after adding your real content/images to confirm 90+ scores across all four categories, and compress any large images before committing them.
